# Five-minute demo script

1. Open the dashboard and generate the default motor-monitoring project.
2. Start **Normal** simulation; show MQTT → validation → ONNX inference and history.
3. Switch to **Abnormal vibration**; show score, reason code and persisted trend.
4. Open **Alerts**; acknowledge an event, add a maintenance note, then resolve it.
5. Export alert CSV and show the device rule controls.
6. Run the ONNX benchmark; explain warm-up, P50/P95 and saved evidence.
7. Show TensorRT as unavailable on Mac, then open a real Jetson `REPORT.md` when available.
8. Close with ESP32 firmware and PostgreSQL deployment topology.

Never present local CPU timing as Jetson performance. Label hardware-dependent steps.
